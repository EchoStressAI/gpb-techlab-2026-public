# Model Card · CASE 1 — риск внешнего психологического воздействия

## 1. Назначение

CASE 1 формирует дополнительный сигнал риска того, что клиент может находиться под внешним психологическим воздействием во время разговора.

Система не определяет личность мошенника и не утверждает факт мошенничества. Она помогает выделить звонки, требующие дополнительного внимания в антифрод-процессе.

## 2. Аналитический горизонт

**Первые 60 секунд** релевантной клиентской речи.

Ограничение 60 секунд является частью контракта. Последующий разговор не должен протекать в раннюю оценку и создавать временную утечку.

## 3. Анализируемая роль

Основной объект анализа — **CLIENT**.

Данные оператора могут использоваться для технического построения диалога, но не должны автоматически становиться модельным сигналом клиента.

## 4. Вход

Минимальный вход публичного integration layer:

- аудиофайл;
- `case_id=CASE_1`;
- опциональные метаданные звонка.

Локальный runtime отвечает за case-specific preprocessing и model inference.

## 5. Выход

Ожидаемый semantic output runtime:

- `case_id`;
- `model_id`;
- `analysis_horizon_sec=60`;
- `status`;
- risk/primary score;
- decision/status;
- quality information;
- supporting/XAI fields, если они предусмотрены runtime.

Публичный gateway валидирует контракт, но не пересчитывает закрытый model score.

## 6. Интерпретация score

Score следует трактовать как **модельный сигнал риска**, а не как доказательство преступления и не как вероятность в юридическом смысле, если конкретный runtime явно не определяет калиброванную вероятность.

Рекомендуемая продуктовая логика:

```text
модельный сигнал
   +
качество данных
   +
операционный контекст
   ↓
дополнительная проверка / рекомендация
```

## 7. Evidence / insufficient-data behavior

Если в первых 60 секундах нет достаточного клиентского материала, система должна уметь вернуть отдельный статус недостаточности данных.

Недостаточность входа не должна автоматически становиться «низким риском».

## 8. Объяснимость

CASE 1 explanation должен отвечать на вопросы:

- достаточно ли клиентской речи попало в окно;
- какой model runtime использован;
- какие наблюдаемые категории факторов поддерживают результат;
- есть ли ограничения качества;
- является ли решение окончательным или требует проверки.

Публичная документация намеренно не содержит внутренние коэффициенты scorer, proprietary feature engineering и универсальные интегральные правила EchoStressAI.

## 9. Известные риски

- короткая клиентская речь;
- перекрытия говорящих;
- ошибки channel/speaker routing;
- ASR-ошибки, если textual branch используется конкретным runtime;
- domain shift на других типах звонков;
- изменение поведения клиентов после первых 60 секунд;
- возможная корреляция модельного сигнала с неспецифичным стрессом, а не только с воздействием мошенника.

## 10. Корректное использование

CASE 1 следует использовать как один из сигналов системы поддержки решений. Он не предназначен для автоматической блокировки клиента без банковских правил, проверки и допустимого процессом контроля.

## 11. Версионирование

`model_id` приходит от подключённого runtime. Публичный integration layer не должен скрывать замену модели под прежним идентификатором.
