# Human Explainability Acceptance · HR Reviewer Form

Этот form соответствует frozen protocol проверки объяснимости для Case 2. Он оценивает человеческую понятность и actionability product explanation, а не качество самой ML-модели.

## Инструкция HR reviewer

Для каждого предоставленного безопасного explanation case:

1. посмотрите итоговый relative risk/state signal;
2. прочитайте public-safe explanation факторов;
3. обратите внимание на quality/history limitation и следующий шаг;
4. ответьте на четыре вопроса по шкале 1–5;
5. при желании оставьте комментарий, что было непонятно или что нужно изменить.

Reviewer не показывается ground truth до ответа и не требуется угадывать «правильный» label.

## Frozen acceptance rule

Основной показатель строится по Q2 и Q3.

Одна respondent-case assessment считается успешно понятой и применимой только если одновременно:

```text
Q2 >= 4
AND
Q3 >= 4
```

Итог:

```text
Explainability Acceptance Rate =
  число оценок, где Q2>=4 и Q3>=4
  / число всех валидных respondent-case оценок
```

PASS по критерию:

```text
Explainability Acceptance Rate >= 0.80
```

Дополнительно отдельно публикуются:

- Q1 clarity rate = доля Q1 >= 4;
- Q2 feature clarity rate = доля Q2 >= 4;
- Q3 actionability rate = доля Q3 >= 4;
- Q4 safety clarity rate = доля Q4 >= 4;
- число уникальных HR respondents;
- число explanation cases;
- число валидных respondent-case ratings;
- по возможности 95% CI.

ТЗ не задаёт минимальное число респондентов, поэтому sample-size threshold не придумывается. Если выборка мала, это указывается как ограничение.
