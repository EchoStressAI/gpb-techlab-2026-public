# Human Explainability Acceptance · Reviewer Form

Этот form предназначен для независимой оценки понятности объяснений результата. Он не просит reviewer оценивать корректность самой ML-модели и не раскрывает proprietary internals.

## Инструкция reviewer

Для каждого предоставленного безопасного demo/review case:

1. посмотрите итоговый PRIMARY результат;
2. прочитайте public-safe explanation / quality / limitation block;
3. ответьте на два основных вопроса ниже;
4. при желании оставьте короткий комментарий.

Не пытайтесь угадывать правильный label и не используйте внутреннюю информацию о модели.

### Q1. Понятно ли вам объяснение результата?

- [ ] Да
- [ ] Нет

При ответе «Да» reviewer должен понимать как минимум:

- что означает итоговый signal/status;
- что это не автоматически probability/diagnosis;
- есть ли ограничения качества/evidence, влияющие на интерпретацию.

### Q2. Можно ли использовать это объяснение для выбора следующего действия в рамках заявленного decision-support сценария?

- [ ] Да
- [ ] Нет

Здесь оценивается не автономное решение системы, а пригодность explanation для human-in-the-loop следующего шага.

## Правило подсчёта

Одна assessment считается положительной только когда одновременно:

```text
Q1 = Да
AND
Q2 = Да
```

Observed acceptance rate:

```text
positive assessments / all valid assessments
```

Технический критерий `≥80%` считается достигнутым на конкретном survey dataset только если observed joint acceptance rate ≥0.80.

Размер и состав reviewer sample должны публиковаться рядом с результатом; сам факт ≥80% на маленькой/нерепрезентативной выборке не превращается автоматически в доказательство внешней обобщаемости.
