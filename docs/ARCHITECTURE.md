# Архитектура публичного GPB submission

## Цель

Публичный репозиторий содержит воспроизводимый интеграционный слой двух кейсов и стабильный контракт подключения model runtime. Модельная реализация может поставляться отдельным локальным процессом/контейнером без раскрытия исследовательского и обучающего кода.

## Поток данных

```text
Client / UI
    |
    v
Public FastAPI integration layer
    |
    +-- CASE_1 --> local runtime adapter --> CASE 1 runtime (<=60 sec)
    |
    +-- CASE_2 --> local runtime adapter --> CASE 2 runtime (<=180 sec)
    |
    v
Unified response
```

## Почему runtime отделён

Это позволяет одновременно:

1. оставить публичным API, маршрутизацию, deployment и acceptance-контракт;
2. не публиковать данные, training notebooks и внутреннюю исследовательскую реализацию;
3. подключать runtime локально, без зависимости от внешнего облачного API;
4. проверять доступность моделей через `/readiness`;
5. исключить генерацию фиктивных score при отсутствии модели.

## Сценарии

| Case | Аналитическое окно | Назначение |
|---|---:|---|
| CASE_1 | 60 сек | дополнительный сигнал риска внешнего воздействия/управления клиентом |
| CASE_2 | 180 сек | оценка состояния сотрудника / риска выгорания и объяснимых факторов |

## Fail-closed поведение

Если runtime отсутствует, недоступен или нарушает контракт, интеграционный API не подставляет константы и не симулирует результат. Возвращается явный статус ошибки (`MODEL_RUNTIME_UNAVAILABLE` или `MODEL_RUNTIME_CONTRACT_ERROR`).

## Данные

Публичный репозиторий не содержит исходные звонки, транскрипты пользователей, банковские метки или иные персональные/закрытые данные.
