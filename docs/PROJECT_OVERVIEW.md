# Обзор проекта

## 1. Назначение

EchoStressAI для GPB TechLab 2026 — прототип системы анализа телефонных разговоров для двух прикладных банковских сценариев:

- **CASE 1 — риск внешнего психологического воздействия на клиента** во время разговора;
- **CASE 2 — риск неблагоприятного состояния сотрудника**, связанного с утомлением/истощением и снижением работоспособности.

Система предназначена для поддержки специалиста и не заменяет человека, службу безопасности, психолога, врача или HR-решение.

## 2. Почему два разных кейса реализованы раздельно

Оба сценария используют голос и речь, но решают разные задачи, имеют разные целевые роли и разные временные окна.

| Параметр | CASE 1 | CASE 2 |
|---|---|---|
| Анализируемая сторона | клиент | сотрудник поддержки |
| Рабочее окно | первые 60 секунд | первые 180 секунд |
| Основной смысл | дополнительный сигнал риска влияния | сигнал состояния сотрудника |
| Результат | score/status + объяснения | score/status + объяснения |
| Использование | помощь в антифрод-процессе | помощь руководителю/HR/операционному контролю |

Поэтому в публичном API оба сценария имеют общий транспортный слой, но отдельные model runtime.

## 3. Основной пользовательский сценарий

```text
WAV/MP3 upload
      ↓
проверка файла и метаданных
      ↓
определение CASE 1 / CASE 2
      ↓
ограничение окна 60 / 180 секунд
      ↓
case-specific runtime
      ↓
score + quality + explanation
      ↓
унифицированный API-ответ
```

## 4. Что делает публичный репозиторий

Публичная часть отвечает за:

- стабильный API;
- маршрутизацию кейсов;
- ограничения аналитического горизонта;
- readiness/health;
- передачу аудио в локальный runtime;
- проверку контрактов ответа;
- Docker-запуск интеграционного слоя;
- smoke/contract tests;
- документацию.

## 5. Что находится за границей публичного репозитория

Не публикуются:

- банковские и исследовательские аудиозаписи;
- транскрипты с персональными данными;
- training notebooks;
- внутренние feature-selection и ablation-пайплайны;
- универсальная интегральная методология EchoStressAI;
- персональная норма и внутренние правила longitudinal fusion;
- закрытые коэффициенты/эвристики, не требуемые публичным контрактом;
- приватные model weights и serving artifacts, если их публикация не разрешена отдельно.

## 6. Почему runtime вынесен отдельно

Такой дизайн решает сразу несколько задач:

1. Публичный код можно читать и запускать без доступа к закрытым моделям.
2. Модельный runtime можно обновлять независимо, сохраняя API.
3. Отсутствующая модель не подменяется заглушкой с «правдоподобным» числом.
4. Для on-prem сценария runtime может работать локально рядом с API без внешней передачи аудио.

## 7. Принцип fail-closed

Если case runtime не настроен, недоступен или возвращает ответ, нарушающий контракт, система не генерирует score сама. Вместо этого возвращается явный технический статус недоступности.

Это принципиальная часть проекта: техническая доступность и качество модели не маскируются интерфейсом.

## 8. Стадия проекта

Репозиторий — публичный интеграционный слой конкурсного решения. Он развивается по allow-list принципу: новый код добавляется только после проверки, что он необходим для воспроизводимости/интеграции и не раскрывает закрытые данные или универсальное know-how EchoStressAI.
